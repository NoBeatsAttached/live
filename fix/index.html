Read first — prep your project

If you get picked, we need your actual Ableton project — prepped so it opens clean on G-REX's machine. If it's not prepped, it won't open right and we move to the next winner. Here's the whole checklist:

  1. Bounce your MIDI and any non-Ableton plugins to audio. G-REX doesn't have your VSTs (Serum, Vital, Kontakt, etc.), so those tracks need to become audio first. Two ways, whichever you know: (a) Freeze & Flatten — right-click the track name → Freeze Track, then right-click again → Flatten. Or (b) bounce/export the track to audio and drag it back in — either one turns the VST's sound into a plain audio clip anyone can open. Do this for every track running a third-party plugin or instrument. Want the notes visible too? Duplicate the track and mute the MIDI copy before you bounce the other one.
  2. Leave stock Ableton devices alone. Anything built into Ableton (Operator, Wavetable, stock effects) opens fine on his end — only third-party stuff needs bouncing.
  3. Pack it into one file — this is the step people miss. Don't zip a folder, and don't send a bare .als — it'll open with "samples missing" on his machine. In Ableton: View → File Manager → Manage Project (older versions: File → Manage Files). Look at the External Files section: if it lists anything, that's your samples living outside the project — hit Collect and Save first. Once that section is clear, hit Create Pack at the bottom, name it, and save. You get one .alp file with the whole project inside, about half the size.
  4. Upload & share. Drop the .alp on Google Drive or Dropbox, set sharing to "anyone with the link," and paste that link in the form below. (If Create Pack gives you trouble, a zipped project folder still works — just run File → Collect All and Save first, then zip the whole folder.)
